## 進め方

確認を省いて結果まで進める。途中でユーザーに質問せず、下の 3 つの分岐のどれかで終える。

1. 上の「レポートの場所」にある takt のレポートを読む。判定と指摘（`TAKT evaluation failed` のコメントの内容も含む）を確かめる。
2. 指摘の中身で、次の 3 つのどれかに進む。

### 分岐 1: コードの指摘の場合

コードに直す点がある指摘なら、直してテストを通す。commit して、上の「head ブランチ」へ、上に書いた push のコマンドで push する。push すれば PR の head が変わり、takt が新しい head でレビューをやり直す。やり直しの印は書かない。

### 分岐 2: 証跡が無いだけの場合

指摘が「証跡が無い」ことだけなら（コードは正しく、テストの実行結果などの根拠が PR に載っていない）、証跡を PR の本文かコメントに載せる。そのあと、上の「やり直しの印」の 1 行だけを本文にしたコメントを PR に付ける。コードは変えない。

### 分岐 3: 直せない場合

直せないなら、直せない理由を PR のコメントに書いて止まる。push も、やり直しの印も書かない。

## 変えないもの

issue の本文・完了条件・ラベルを変えない。変える必要があるなら、直せないものとして分岐 3 で止まる。
