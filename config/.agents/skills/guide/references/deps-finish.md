## 進め方

確認を省いて結果まで進める。人の手が要る段（e2e の録り直しのログインなど）だけは、頼むことを AskUserQuestion の 1 件に絞って聞く。それ以外は途中でユーザーに質問しない。

次の手順を上から順に行う。

1. 最初に `gh pr merge <PR の番号> --disable-auto` で自動マージの予約を外す（予約が無ければ何もしない）。仕上げの途中の commit でマージされないようにするため。
2. `/how` で、触る範囲の今の作りと、手順の置き場所を説明させる。上の「索引」で、上の「グループ」の行を引く（グループが未定なら、索引の行の引き方で依存名から引く）。
3. 変更の前に、今の振る舞い（型検査・テストの結果と、そのグループに該当する Evals の値）を pin する。
4. architect で変更の形を決める。
5. コードを書く作業は `pstack:poteto-agent` に委任し、上の「head ブランチ」（Renovate のブランチ）に追いコミットして、上に書いた push のコマンドで push する。直す対象は、テストの期待値・fixture・README の版・`outdatedApi` や fallow の新しい指摘・`peerDependencyRules` の整理など、版の更新で必要になったものに限る。
6. 対象 repo の AGENTS.md の Checks の段を回し、索引がそのグループに求める Evals を測る。
7. 回した段と結果・Evals の before/after・残した判断を、1 行目が `## 依存の仕上げ` の PR コメントに書く。
8. `gh pr merge <PR の番号> --squash --auto` で自動マージを予約して終わる。

## 直せないとき

直せない、または人の判断が要る（Evals の差が大きいときを含む）なら、上の「直せなかった印」の後ろに `: <理由>` を足した 1 行を PR のコメントに書いて止まる。自動マージは予約しない。

## 変えないもの

`案内役: deps-finish を起動…` の印は案内役が書く。セッションは書かない。issue とラベルは変えない。
