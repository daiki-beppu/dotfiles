# Codex Cloud setup

対象環境の最終設定が保存され、Cloud 上でセットアップ・メンテナンスと必要なプロジェクト動作を確認できたら完了。設定案やクリックだけを保存・検証済みと扱わない。

## 構成を決める

[公式 Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environment) と現行 UI で、変更する設定の仕様を確認する。通信設定を変える場合は Internet access の文書も参照する。

Git remote と最新の取得可能なデフォルトブランチ SHA を特定し、ランタイム、依存導入、必要な検証を判断できるマニフェスト・CI・スクリプトを読む。未 push の構成を Cloud が取得できるものとして扱わない。

Browser / Computer Use でアカウント・リポジトリ・環境を照合する。対応する既存環境を更新し、なければ作成する。用途の異なる候補を識別できない場合だけ対象を確認する。

## 設定と検証

- ランタイムはリポジトリの制約と Cloud の選択肢から選ぶ。自動セットアップで足りなければ手動にする。
- セットアップは初期導入、メンテナンスはキャッシュ復元後の再同期として、ロックを尊重し再実行可能にする。
- Node.js / Vite+、Playwright、PDF 生成を使う構成は [構成別の注意点](references/runtime-validation.md) を読む。
- Secrets と環境変数は必要な利用段階に合わせて配置し、値は出力しない。セットアップ内の `export` は後続のエージェント段階への永続化にならない。
- 依頼済みの作成・更新・テスト・保存を再確認で止めない。権限や通信の拡張は実際に必要な操作と既存承認を照合する。

Cloud のテスト完了表示と各処理の成功を確認する。独立した後続シェルで SHA、ランタイム、PATH、ツールの利用可否を確かめ、対象構成のチェック・ビルドや必要なブラウザ／サービスの起動を検証する。親の export を継承した子シェルだけでは永続化の証拠にならない。

環境の失敗は設定を修正して影響する経路を再検証する。大量ログは必要な末尾と終了状態を取得し、アクセシビリティ表示の省略だけで停止と判断しない。UI で独立シェルやキャッシュ復元経路を検証できなければ未検証と記録する。

環境設定の依頼にコード修正・実装タスクの起動・デプロイを含めない。既存コードの失敗と環境構築の失敗を区別する。

## 保存と完了

UI の順序に応じて保存し、開き直して対象と最終値の保持を確認する。保存応答が不明なら一覧と設定を再確認し、重複作成を避ける。テスト後に値を変えた場合は影響する確認をやり直す。

環境リンク、対象 SHA、主な設定、セットアップ／メンテナンスとプロジェクト検証結果を報告する。未配置・既存警告／失敗・未検証を成功に含めない。
