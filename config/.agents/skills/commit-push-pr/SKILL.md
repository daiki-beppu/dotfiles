# Commit, push, PR

手元の変更を PR にし、最新 head SHA の CI green まで対応する。
ユーザーが commit のみなど範囲を指定した場合は、その範囲に従う。

## 進め方

1. リポジトリの指示と差分、ブランチ、既存 PR を確認し、今回の変更を特定する。
2. 利用可能なスキル一覧を確認する。commit・PR 作成・CI 修復などに流用できる
   ビルトインスキルがあれば、該当する場面で積極的に定義を読み、その手順を使う。
   既存 stack の操作には `gh-stack` を読む。利用できない場合は `git` と `gh` で進める。
3. 必要な検証を行い、今回の変更だけを commit・push する。
4. PR を作成するか、既存 PR のタイトル・本文を最終差分に合わせて更新する。
5. CI を確認し、失敗時は原因調査・修正・検証・再 push を行う。
   最新 head SHA に適用される CI がすべて成功するまで対応する。

## 完了

PR URL、最新 head SHA、検証・CI の結果を報告する。
CI 未設定や未実行を green と扱わず、権限や外部障害で進めない場合は未完了の理由と
必要な対応を伝える。CI の無効化・弱体化で成功させない。マージは別の依頼で扱う。
