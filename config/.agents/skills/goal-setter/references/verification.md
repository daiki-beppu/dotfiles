# 成果別の検証

成果の種類に応じて、完了判定が変わる項目だけ目標へ入れる。

- **不具合**: 再現する入力と期待結果、関連する回帰の確認。
- **性能**: 測定対象・方法・基準。比較に必要な反復を選び、試行数を一律に増やさない。
- **実動システム**: ユーザーの入力から実際の処理・保存・出力までの最小の一連の動作。公開や外部接続が成果を定義する場合は、その結果も確認する。
- **移行・一括処理**: 対象全件の範囲と件数、成功・失敗・未検証の内訳。
- **調査**: 答える問いと判断に必要な一次資料。仮説がある場合は競合仮説や反証も調べ、未確認を事実上の否定と扱わない。
- **文書や画面**: 使用者が必要な情報や操作に到達できること。既存の正本があるなら更新先を指定する。

長期作業の再開状態が必要なら、既存のタスク管理や簡潔な作業メモで未完了項目・証拠・判断を保持する。新しい管理ファイルを一律には要求しない。

独立レビューや実行実験は、重大な誤り・不足する証拠・広い変更など、追加確認が完了判断を変える場合に選ぶ。通常の編集に必須化しない。ツールが使えず必要な検証ができないときは未検証と報告する。
